================================================================================
                 SECURITAS — RESUMO DO APLICATIVO E DA API
================================================================================
Atualizado em: 20/10/2026

1. VISÃO GERAL
--------------------------------------------------------------------------------
O Securitas é um sistema de rastreamento e segurança veicular. Ele reúne um
aplicativo Android, uma API REST e, opcionalmente, um rastreador GPS instalado
no veículo. O usuário pode cadastrar veículos, acompanhar a telemetria,
consultar rotas e solicitar bloqueio ou desbloqueio remoto.

Fluxo principal:

  Aplicativo Android <-> API Node.js <-> rastreador GPS (hardware)
                              |
                              +-> Firebase (Firestore + Realtime Database)

2. APLICATIVO ANDROID
--------------------------------------------------------------------------------
O aplicativo está no diretório `app/` e foi desenvolvido em Kotlin para Android
(minSdk 26), usando Jetpack Compose e Material 3. Ele se comunica com a API por
HTTP usando OkHttp e armazena preferências, como token e endereço do servidor,
no SharedPreferences.

Principais recursos:

- Cadastro, login e logout de usuários (Firebase Authentication).
- Cadastro, edição, consulta e remoção de veículos.
- Dashboard com a frota e acesso às funções principais.
- Detalhe do veículo com o rastreador vinculado: tipo (GPS real ou simulador),
  estado conectado/offline, último contato e última telemetria recebida.
- Rastreamento: consulta a última telemetria e o histórico de posições.
- Controle remoto: cria comandos de bloqueio e desbloqueio para o veículo.
- Histórico de rotas, com início, término e dados do trajeto.
- Cadastro da localização do próprio celular e associação do dispositivo móvel.
- Configuração do endereço da API e opção de simulação de veículo.
- Integração com Firebase Authentication, Firestore e Realtime Database para
  sincronização complementar.

Telas principais:

  Login, Registro, Dashboard, Cadastro/Detalhe de Veículo, Rastreamento,
  Controle Remoto, Histórico de Rotas, Localização do Dispositivo,
  Configurações e Vínculo de API.

Permissões usadas: acesso à Internet, estado da rede e localização aproximada e
precisa do dispositivo.

3. API BACKEND
--------------------------------------------------------------------------------
A API está em `backend/`. É uma aplicação Node.js (versão 22.5 ou superior) com
Express. Ela centraliza as regras de negócio, a validação de autenticação, os
dados de veículos, a telemetria e a fila de comandos para o hardware. Também
possui uma página de painel web servida na rota `/`.

O banco da API é o Firebase, sem banco local:

- Cloud Firestore (instância `securitas`): contas (`users`), veículos,
  dispositivos rastreadores, telemetria, rotas, comandos e o cadastro do
  celular (`mobile_devices`).
- Realtime Database: última posição de cada veículo (`telemetry/<id>`), resposta
  de comandos (`commands/<id>`) e a última localização do celular
  (`mobile_locations/<uid>`).

A autenticação do aplicativo é feita pelo Firebase Authentication, no próprio
app. A API apenas valida o ID Token recebido. O rastreador usa os cabeçalhos
`x-device-id` e `x-api-key`.

As rotas retornam erros em JSON no formato `{ "error": "mensagem" }`.

4. PRINCIPAIS ENDPOINTS
--------------------------------------------------------------------------------
Públicos:

- `GET /health` — verifica se a API está disponível.
- `GET /api` — apresenta uma referência rápida das rotas.

O registro, o login e o logout são feitos pelo Firebase Authentication: pelo
SDK no app Android e pelo REST do Identity Toolkit no painel web.

Protegidos para o aplicativo (Bearer ID Token do Firebase):

- `/v1/auth/me` — dados do usuário autenticado. `/v1/auth/config` (público)
  entrega a apiKey usada pelo login do painel web.
- `/v1/vehicles` — listar, criar, consultar, editar e excluir veículos.
- `/v1/vehicles/:id/device` — gera as credenciais do rastreador.
- `/v1/vehicles/:id/simulation` — consulta/altera a simulação do veículo.
- `/v1/vehicles/:id/telemetry/latest` e `/history` — consulta telemetria.
- `/v1/vehicles/:id/telemetry/stream` — atualizações em tempo real via SSE.
- `/v1/vehicles/:id/commands` — envia ou lista comandos de bloqueio.
- `/v1/vehicles/:id/routes/start`, `/stop` e `/routes` — gerencia rotas.
- `/v1/routes` e `/v1/routes/:id` — consulta ou remove rotas.
- `/v1/mobile/location` e `/v1/mobile/device` — localização e registro do
  aparelho móvel.

Protegidos para o rastreador GPS:

- `POST /v1/hardware/telemetry` — recebe latitude, longitude, velocidade,
  rumo, bateria e horário.
- `GET /v1/hardware/:deviceId/status` — informa vínculo e estado atual.
- `GET /v1/hardware/:deviceId/commands` — entrega comandos pendentes.
- `POST /v1/hardware/:deviceId/commands/:commandId/ack` — confirma a execução
  de um comando.

Há ainda rotas administrativas (`/v1/admin/*`) para visão geral, consulta de
qualquer veículo da frota, simulação, logs e diagnóstico. Elas exigem
autenticação e são consumidas pelo painel web. Destaques:

- `POST /v1/admin/vehicles/:id/position` — posiciona o veículo manualmente
  (arrastar o marcador no mapa do painel). Atualiza o Firestore, o Realtime
  Database, o SSE e o carimbo que faz o simulador reancorar a rota.
- `POST /v1/admin/firebase/sync` — botão "Sincronizar Firebase": replica as
  contas do Firebase Auth para o Firestore e os celulares registrados
  (`mobile_devices`) do Firestore para o Realtime Database.

5. TELEMETRIA, COMANDOS E TEMPO REAL
--------------------------------------------------------------------------------
Quando o hardware envia uma posição, a API grava a telemetria, atualiza a última
posição do veículo e, se houver uma rota em andamento, acrescenta o ponto ao
trajeto e calcula a distância. Em seguida, publica o evento para os clientes
conectados por Server-Sent Events (SSE).

O bloqueio funciona por fila: o aplicativo cria um comando `block` ou `unblock`;
o hardware o consulta, executa a ação e envia uma confirmação. A API então muda
o estado do comando e do veículo e notifica os clientes conectados.

5b. COMO OS DADOS SÃO GUARDADOS (E O LIMITE DO PLANO GRATUITO)
--------------------------------------------------------------------------------
O Firestore guarda o histórico (telemetria ponto a ponto, rotas, veículos,
contas). A posição do instante presente e as últimas posições ficam também no
Realtime Database, que é o que a API lê para responder "onde está o veículo
agora". Isso não é redundância: o plano gratuito do Firebase (Spark) permite
50 mil leituras e 20 mil escritas por dia, e o projeto precisa funcionar bem
dentro desse limite.

Como a cota é pequena, a API foi construída para nunca depender de uma leitura
carreta:

- A posição ao vivo mora no Realtime Database (`telemetry/{vehicleId}`), com um
  anel dos últimos 300 pontos (`telemetry_history/{vehicleId}`). Ler a posição
  custa uma leitura do RTDB e nenhuma do Firestore.
- Veículos e rastreadores são espelhados no RTDB (`vehicles_mirror` e
  `devices_mirror`). Quando a cota de leitura do Firestore acaba, a API
  responde com o espelho em vez de devolver erro ao aplicativo.
- A ingestão grava primeiro no RTDB e só depois no Firestore; se o Firestore
  falhar, a posição continua sendo reportada ao app.
- O documento do veículo e o do rastreador são regravados no máximo a cada
  120 segundos, e o documento da conta a cada 5 minutos.
- O painel administrativo nunca varre a coleção de telemetria.
- A autenticação do hardware tem um cache local das credenciais
  (`backend/.run/device-keys.json`, ignorado pelo git), para que nenhum
  rastreador pare de reportar só porque a cota acabou.
- Para manter a coleção de telemetria pequena existe
  `node src/prune-telemetry.js 400`, que apaga os pontos antigos mantendo os
  400 mais recentes de cada veículo.

6. EXECUÇÃO LOCAL DA API
--------------------------------------------------------------------------------
No diretório `backend/`:

  npm install
  npm start

A API inicia, por padrão, em `http://localhost:3000`. Comandos adicionais:

  npm run simulator  simula um rastreador GPS
  npm run api        sobe a API + um simulador por rastreador cadastrado

Para subir a API é necessário o Firebase: coloque a chave da conta de serviço em
`backend/firebase-service-account.json` e preencha o `.env` (use `.env.example`
como referência).

7. FIRMWARE DO RASTREADOR (ESP32)
--------------------------------------------------------------------------------
O firmware do rastreador fica em `hardware/firmware` (PlatformIO/Arduino) e está
documentado em `hardware/LIGACOES_DE_PORTA.txt` (pinagem, BOM e fiacao) e
`hardware/README.txt` (gravação e diagnóstico).

O hardware previsto é um ESP32 DevKit V1 com:

- GPS u-blox NEO-M8N (UART2, pinos 16/17);
- modem 4G SIM7600G-H (UART1, pinos 25/26, PWRKEY no 27) como alternativa ao
  Wi-Fi;
- receptor RF 433 MHz (RXB6/SYN480R) no GPIO 34;
- relê de corte da ignição (PC817 + 2N2222 + 1N4007) no GPIO 23;
- leitura de bateria do pack 3S por divisor de tensão no GPIO 36;
- LED de status no GPIO 2.

O firmware conversa com a API usando exatamente o protocolo documentado em
`backend/API_ESTRUTURA.txt` (seção 7): cabeçalhos `x-device-id` e `x-api-key` em
todas as chamadas. Ele valida as credenciais no boot, envia telemetria a cada
10 s, consulta os comandos de bloqueio a cada 15 s e emite um heartbeat a cada
60 s — o heartbeat mantém o rastreador marcado como "online" no painel mesmo
quando o GPS ainda não fixou posição (bancada, sem módulos ligados).

As credenciais (`DEVICE_ID` e `API_KEY`) são geradas pela API em
`POST /v1/vehicles/:id/device` e gravadas em `hardware/firmware/src/secrets.h`,
que não é versionado (use `secrets.example.h` como modelo).

Para sobreviver à rede instável da faculdade, o firmware conhece duas redes
Wi-Fi (principal e reserva) e até três endereços da API: ele cai na segunda
rede quando a primeira não responde e usa o primeiro endereço da API que
responder, mantendo-o enquanto ele funcionar. O cliente HTTP foi escrito
sobre `Client*` (em vez da classe `HTTPClient` do core do Arduino, que só
aceita `WiFiClient&`), para que Wi-Fi e 4G compartilhem exatamente o mesmo
código.

8. PAINEL WEB DO ADMINISTRADOR
--------------------------------------------------------------------------------
Servido pela própria API na raiz (`/`), em HTML e JavaScript puro. Faz login
com o Firebase Authentication (REST Identity Toolkit) e usa o ID Token como
Bearer em todas as chamadas administrativas.

Além da visão geral da frota, dos logs e do diagnóstico, o painel permite
posicionar o veículo manualmente arrastando o marcador no mapa e sincronizar o
Firebase (botão "Sincronizar Firebase"), que replica as contas do Auth para o
Firestore e os celulares registrados para o Realtime Database.
